About ecdh.chat

Private chat that leaves nothing behind.

ecdh.chat connects two people directly, encrypts everything end to end, and keeps no accounts, no history and no copies. When the chat ends, it's gone.

Start a chat Get the desktop app

Built around three promises

No sign-up and no phone number. Open a link and talk, in your browser or in the desktop app for Windows and Linux.

Straight to the other person

Messages, files, voice notes, calls and screen sharing travel directly between the two of you. Our server only introduces you, then steps out of the way.

Encrypted end to end

Fresh keys are made for every chat and never leave your device. Not even our server can read or change what you send.

Nothing is stored

No accounts, no message history, no backups. Messages live only on your two screens and disappear when the chat ends.

How a chat works

Every chat follows the same short path.

  1. You get a one-time invite link

    It contains a random room name and a 128-bit secret. The secret sits after the #, the part of a link that browsers never send to a server.

  2. The server introduces you

    When the other person opens the link, the server passes the connection setup between your two devices. It never receives the secret.

  3. Your devices connect directly

    A peer-to-peer WebRTC connection is made. With Hide my IP on, it goes through our relay instead, which only ever sees encrypted data.

  4. A fresh key exchange locks the chat

    Both devices make new keys and mix in the secret from the link, so only someone holding that exact link can join the conversation.

  5. You compare a 6-digit code

    Read it to each other over a call or in person. If the codes match, nobody is in the middle, not even someone who got hold of the link.

  6. Either of you ends it

    Ending the chat wipes it from both screens. The link can't be used again.

Security in detail

For people who want to check our work. All of this happens on your device, using the cryptography built into the browser (Web Crypto) and WebRTC.

Key exchangeEphemeral ECDH on the P-256 curve, new for every chat. Private keys can't be exported and are discarded as soon as the chat keys are made.
CommitmentWhoever made the room commits to their public key with SHA-256 before seeing the other one, so an attacker can't try key after key until the codes happen to match.
Key derivationHKDF with SHA-256. The salt is the 128-bit secret from the invite link. The context covers the room, both public keys and both WebRTC (DTLS) certificate fingerprints.
EncryptionAES-256-GCM, with a separate key for each direction. A message counter is the nonce, so a replayed, dropped or reordered message fails to decrypt and the chat closes.
Proof of matching keysEach side's first encrypted message carries a hash of everything above. If anything differs, the chat closes before a single message is shown.
Verification codeSix digits derived from the same keys and context. Matching codes prove the two of you are connected to each other directly.
CallsAudio, video and screen sharing use WebRTC's DTLS-SRTP encryption. Because the certificate fingerprints feed into the code, the code check covers calls too. Call setup travels over the encrypted chat, never through the server.
Files and photosSent in encrypted chunks, up to 100 MB per file. Photos are redrawn before sending, which removes location and camera details, unless you choose to send the original.
Invite linksA link works for one person only. An unused link expires after 30 minutes.
Linux appLinux's web engine has no WebRTC, so the Linux app makes the connection itself, with the open-source webrtc-rs library inside the app. Everything above runs unchanged on top of it, and the code covers its certificate fingerprints just the same. Calls aren't in the Linux app yet.

What our servers can and can't see

Being clear about this matters more than sounding perfect.

Never What stays private

  • Your messages, files, voice notes and calls
  • The secret in your invite link
  • Your encryption keys and verification code
  • Who you are: there are no accounts, names or phone numbers

Briefly What the server handles

  • Your IP address and the other person's, while connecting
  • The room name and when a chat starts
  • Connection setup data: network addresses and certificate fingerprints
  • With Hide my IP, the relay sees both IP addresses and how much encrypted data flows, but never what's in it

Nothing goes into a database. Waiting rooms exist only in the server's memory, and our web server and relay don't keep logs of individual chats.

No trackers, no third parties

Nothing watching you

No analytics, ads, cookies or tracking pixels. Nothing is loaded from other companies: no fonts, no scripts, and the connection checks run on our own server.

A locked-down page

HTTPS everywhere with HSTS, a strict Content Security Policy and Trusted Types, so text from the other person can never run as code on your screen.

Even tighter in the app

The desktop app carries its own copy of the code instead of loading it from the server, and its source is public, so you can build it yourself. It can blur the chat when you look away, and on Windows also hide its window from screenshots and screen sharing.

Good to know

Every tool has limits. These are ours.

You both need to be online

No server holds your messages, so a chat happens live, while you both have it open.

The other person can see your IP

That's how direct connections work. Turn on Hide my IP to send everything through our relay instead.

The website trusts our server

Like any web app, the page comes from our server each time you open it. The desktop app avoids this by shipping its code with the app.

Your device has to be safe

Encryption can't protect against malware on a device, someone looking over your shoulder, or a camera pointed at the screen.
